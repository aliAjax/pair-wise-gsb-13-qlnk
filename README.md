# 加油站班次交接 · 油品损溢核销台

按油品录入开始罐存、结束罐存、罐温、付油量与回罐量，温度修正后自动核算账面量、
实存量与损溢；超千分之三强制归因，复核冻结后更正另建版本链。

- 行业：石油
- 技术栈：Vue 3 + Pinia + Element Plus、Vite、TypeScript
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 测试：`npm test`（Vitest，27 个用例覆盖计算、规则、存储版本链与状态层闭环）
- 数据默认保存在浏览器 `localStorage`（键名 `fuel-shift-reconciliation:v1`），
  首次打开自动载入演示数据，页面可一键“重置演示数据”。

## 业务规则

1. **同油品同班不得重复**：一个班次内同一油品只有一条生效记录；待复核阶段在 v1 上修订，
   已复核班次只能走“更正”。
2. **温度修正与损溢口径**（见 `src/domain/calculations.ts`，页面与复核判定共用同一实现）：
   - 体积温度修正：`V20 = Vt × [1 + β × (20 − t)]`（β 为各油品体积温度修正系数）；
   - 账面量 = 修正后开始罐存 + 回罐量 − 付油量；
   - 实存量 = 修正后结束罐存；
   - 损溢量 = 实存量 − 账面量（正溢负损），损溢率 = |损溢量| / |账面量|。
3. **千分之三归因**：损溢率严格大于 `0.003` 时，必须在“计量原因 / 漏损原因 / 操作原因”中
   选一，并填写归因依据；**未归因不得复核**。
4. **复核冻结**：复核通过后班次锁定、当前生效版本及原始罐温永久冻结；表头不可再改、
   不可新增原始油品、不可删除。
5. **更正版本链**：更正必须填写更正原因，旧版本置 `supersededAt` 并冻结（原始罐温随版本保留），
   新版本为“待复核”，重新复核后冻结；待复核更正存在时不能叠加更正。
6. **冲突展示**：冲突统一列出类型、班次、油品、原值/现状、说明与违反的规则条文；
   数据完整性（断链/悬挂/多生效版本）也在每次载入时全量检测。

## 分层结构（数据、计算、存储、页面分开）

```
src/
├── domain/            # 数据 + 计算层：纯 TS，无 DOM、无 IO
│   ├── types.ts       #   领域模型（班次、录入版本、冲突）
│   ├── rules.ts       #   规则常量与条文（千分之三、口径文案、油品档案）
│   ├── calculations.ts#   VCF 温度修正、账面量/实存量/损溢、归因判定（纯函数）
│   └── validation.ts  #   录入校验、全量冲突检测、复核阻断项
├── storage/           # 存储层：规则化读写 + 可替换持久化后端
│   ├── backend.ts     #   StorageBackend：LocalStorageBackend / MemoryBackend（测试用）
│   ├── repository.ts  #   ShiftRepository：班次、录入、复核、更正、删除的唯一写入口
│   ├── errors.ts      #   RuleViolationError（携带冲突明细）
│   └── seed.ts        #   演示数据（已复核 / 待复核未归因 / 更正链）
├── store/
│   └── shiftStore.ts  # 状态胶水：Pinia，写后重载快照、派生视图与冲突
├── components/        # 页面层（Vue 组件，只通过 store 交互）
│   ├── ShiftBar.vue       # 班次选择 / 新建 / 重置
│   ├── EntryForm.vue      # 录入与更正表单（实时损溢、归因必填控制）
│   ├── EntryTable.vue     # 当班油品损溢表（冻结标记、更正、复核）
│   ├── VersionChain.vue   # 版本链时间线（原始罐温、原因、依据）
│   └── ConflictPanel.vue  # 冲突列表（油品、原值、规则）
└── App.vue            # 页面组装：指标 + 录入 + 冲突 + 损溢表
tests/                 # calculations / repository / store 三组测试
```

只持久化原始录入，损溢等派生量不入库，每次读取经计算层重算，保证刷新后
班次、损溢、归因与版本链一致。后端换成 HTTP 接口时只需新增一个 `StorageBackend` 实现。
